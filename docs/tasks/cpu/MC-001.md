# MC-001 — Implement Multicore CPU (SMP, N cores, shared bus)

## Description

Multiple CPU cores sharing one SystemBus + RAM (SMP), configurable core count (>2). Deterministic stepping first; parallel + cache coherence later. Includes step-path optimization.

## Acceptance Criteria

1. Motherboard hosts N cores (N configurable, >2) sharing one bus + RAM.
2. Each core has independent register file / PC / SP; no shared mutable Bit/register state.
3. System step advances each non-halted core one instruction deterministically; run stops when all cores halt.
4. Per-core state inspectable (for GUI).
5. Step path allocation-free (perf).

## Notes

Start deterministic sequential stepping across cores; cache coherence (MESI) is a later phase gated on CACHE-001. Step optimization required: the CPU step path must be zero-allocation so N cores x many steps stays fast.

## Blueprint

### Goal

Turn the single-core machine into an SMP multicore: N CPU cores (configurable, more than 2) sharing one SystemBus and RAM, stepped deterministically, as the foundation for later cache coherence and parallel execution.

### In Scope

- Generalize Motherboard from one Cpu to a Cpu[] (configurable N).
- Each core owns its own SpecialRegisters + RegisterFile; only the bus + RAM are shared.
- stepSystem() advances each non-halted core one instruction per tick (round-robin / lockstep).
- runSystem() runs until all cores halt; per-core HALT tracked.
- Expose per-core state for the GUI.
- Step-path optimization: eliminate per-step heap allocation so N cores scale.

### Out of Scope

- Cache coherence / MESI (later phase, depends on CACHE-001).
- True OS-thread parallelism (start with deterministic sequential stepping).
- Inter-core interrupts / IPIs (ADV-001).
- Atomics / locks / memory barriers (later).

### Topology

motherboard -> Cpu[0..N-1] -> shared SystemBus -> RAM. Cores hold independent register/PC/SP state; memory is shared. Later: per-core L1 cache (CACHE-001) + a coherence protocol (MESI) arbitrated over the shared bus.

### Steps

- Refactor Motherboard to hold and manage a Cpu[] with lifecycle (powerOn/reset/step/run) over all cores.
- Confirm each Cpu instance owns exclusive register/special-register state (no shared mutable Bit objects across cores).
- Implement deterministic stepSystem(): iterate cores in fixed order, step each non-halted core once.
- Implement runSystem(): loop stepSystem() until every core is halted (with a step budget).
- Optimize the single-core step path to zero-allocation (reuse preallocated Word/Address scratch) so N cores stay fast.
- Expose per-core snapshots for the GUI.
- Later phase: add per-core L1 + MESI coherence over the shared bus.

### Hazards

- No shared Bit/register objects across cores - each core's state must be exclusively owned (ownership invariant).
- Deterministic step order required while stepping is sequential; document it before any real parallelism.
- Shared-memory races appear once execution is truly parallel - keep sequential first, add synchronization deliberately.
- Performance amplification: N cores x steps multiplies any per-step allocation - the step path MUST be zero-allocation.
- GUI must scale to N cores without per-step full rebuilds (ties to the GUI memory-view perf fix).
