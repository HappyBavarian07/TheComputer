# FPU-001 — IEEE-754 64-bit Floating-Point Unit

## Description

Bit-level IEEE-754 double-precision (binary64) math coprocessor: FloatAdderSubtractor, FloatMultiplier, FloatDivider, FSQRT, FCMP, and int<->float converters (FCVT), wired into a new opcode category 0x6_. Handle special values (+-0, +-inf, subnormals, quiet/signaling NaN) and round-to-nearest-even. Was explicitly out-of-scope of ISA-002 to keep the integer migration clean.

## Acceptance Criteria

1. Float add/sub/mul/div produce correct binary64 results including special values and round-to-nearest-even.
2. FCVT int<->float correct (truncation/rounding as specified).
3. New 0x6_ opcodes decode and execute; hot path is zero-allocation.
4. Comprehensive tests: boundary values, special values, and round-trip conversions.

## Notes

Open design decision: dedicated 32 x 64-bit float registers (F0-F31, RISC-V style) vs reusing R0-R31 as raw 64-bit bit patterns (simpler wiring). Circuits live in core.float; the FPU dispatch in cpu.fpu.

## Blueprint

### Goal

A real bit-level IEEE-754 binary64 unit so the machine can do floating-point math, built from the same gate/adder primitives as the integer core, without shortcutting to Java double arithmetic.

### In Scope

- binary64 layout: [sign 1][exponent 11, bias 1023][fraction 52, implicit leading 1].
- FloatAdderSubtractor: exponent align -> mantissa add/sub -> normalize -> round (RNE).
- FloatMultiplier: exponent add (minus bias) -> 53x53 mantissa multiply -> normalize -> round.
- FloatDivider: exponent subtract (plus bias) -> mantissa divide -> normalize -> round.
- FSQRT, FCMP, and FCVT.F.I / FCVT.I.F converters.
- ISA category 0x6_: FADD, FSUB, FMUL, FDIV, FSQRT, FCMP, FCVT_IF, FCVT_FI.
- Special-value handling: +-0, +-inf, subnormals, quiet/signaling NaN.

### Out of Scope

- SIMD / vectorized float (separate phase).
- Extended/quad precision; decimal float.
- Fused multiply-add (FMA) unless trivial to add after the base ops.
- Full IEEE exception flags/traps beyond what the FLAGS model needs (can be a follow-up).

### Topology

core.float (FloatAdderSubtractor, FloatMultiplier, FloatDivider, converters, built on existing adders/shifters) -> cpu.fpu (dispatch) -> cpu.Cpu/isa (0x6_ opcodes, register file: F0-F31 or reused R0-R31).

### Steps

- Decide register model (dedicated F0-F31 vs reuse R0-R31) and add 0x6_ opcodes + operand mappings to the ISA.
- Implement bit-level unpack/pack of binary64 (sign/exponent/mantissa, implicit 1, special-value detection).
- Build FloatAdderSubtractor (align, add, normalize, round-to-nearest-even) with special-value paths.
- Build FloatMultiplier and FloatDivider (exponent handling + mantissa multiply/divide + normalize + round).
- Add FSQRT, FCMP, and the int<->float converters.
- Wire FPU dispatch into Cpu.step for the 0x6_ category; keep the hot path zero-allocation.
- Test against boundary/special values and round-trip conversions.

### Hazards

- Round-to-nearest-even is subtle: guard/round/sticky bits must be tracked through normalization.
- Special values (NaN propagation, signed zero, infinities, subnormals) are the usual correctness sink - test them first.
- Exponent bias off-by-one and implicit-leading-1 handling.
- Bit ownership / zero-allocation contract applies to the float circuits exactly like the integer ones.
- Do not fall back to Java double for the arithmetic - the point is bit-level circuits.
