# ASM-003 — Fix assembler / decoder / spec correctness bugs found while validating the assembly guide

## Description

A batch of verified defects and spec/code mismatches found by actually assembling and running programs while writing docs/ASSEMBLY_GUIDE.md. Every item below was reproduced against this branch's compiled code (not inferred from reading). The CALL/RET bugs from the same investigation are already fixed (90bf884, see docs/reviews/2026-09-28-cpu-call-ret-bug.md) and are not part of this ticket. Workflow: align on the design decisions first (see Notes), Developer implements, Team Lead reviews.

## Acceptance Criteria

1. B1: decode and decodeNullable never throw for any 64-bit word; Disassembler.disassemble(0x80000000L) and the GUI disassembly panel work on arbitrary memory.
2. B2/B3: negative immediates are writable in source and execute with the agreed extension semantics per instruction; assemble -> disassemble -> assemble round-trips negative immediates.
3. B4: using pc/sp/ir/flags as an instruction operand produces a clean diagnostic (or is supported), never a NullPointerException.
4. B5: directive alignment is enforced in one place with one rule, at resolve time, with a clear message; AssemblerCli output matches the GUI export byte-for-byte for programs with unaligned directive data.
5. B6: docs/ISA_SPECIFICATION.md and OpCode.java agree on HALT's opcode and STORER's operand roles (whichever side is chosen as correct).
6. B7/B8: DIV/MOD flag behavior and stack over/underflow exception naming decided and documented.
7. Regression tests exist for every fixed item; all bundled examples in src/main/resources/programs still assemble and run; docs/ASSEMBLY_GUIDE.md section 9 updated to match.

## Notes

Reproductions live in docs/ASSEMBLY_GUIDE.md section 9. The GUI's Save bin (WorkbenchController.assembleToBinary) already writes correct bytes for B5 and has tests; it is the reference for what AssemblerCli should produce.

Decisions to settle at alignment: (a) immediate width and per-instruction extension: the spec says ADDI/SUBI sign-extend but ANDI/ORI/XORI zero-extend, while the CPU currently passes a Java int through Word.set(Number), which sign-extends everything; (b) accepted immediate range: keep tying it to MEMORY_SIZE_BYTES or use the field width (-2^31..2^31-1 signed, 0..2^32-1 unsigned); (c) STORER: is the code (RAM[rs1+off]=rd, same role order as LOADR) or the spec (RAM[rd+off]=rs1) the intended behavior; (d) DIV/MOD: clear C/V like the logic ops, or keep them untouched and document it, and what division by zero should do (not yet characterized); (e) what happens to AssemblerCli: add a main() and keep it, or retire it in favor of the shared in-process pipeline the GUI uses.

## Blueprint

### Goal

Make the assembler, instruction decoder, disassembler and ISA spec agree with each other and with the running CPU, so that what the assembler accepts is exactly what the CPU can decode and execute, and no input crashes a tool.

### In Scope

- B1 (HIGH, decoder): InstructionDecoder.decode and decodeNullable use Math.toIntExact(wordValue & 0xFFFFFFFFL) and throw ArithmeticException for any imm32 >= 2^31. Repro: Disassembler.disassemble(0x0000000080000000L) throws; hand-encoding addi r1, r1, 0xFFFFFFFF crashes Cpu.step. Also violates DIS-001's never-crash-on-arbitrary-bytes requirement.
- B2 (HIGH, assembler): no negative literals - IndexedLexer rejects '-' (unexpected character), and InstructionWordEncoder.imm() only accepts 0..MEMORY_SIZE_BYTES-1 (about 28 bits, positive only) with a stale 'imm16' in its error text.
- B3 (MEDIUM, cpu/spec): immediate extension semantics undefined in practice - spec says sign-extend for ADDI/SUBI and zero-extend for ANDI/ORI/XORI, code sign-extends all via int. Cannot be tested until B1 is fixed.
- B4 (MEDIUM, assembler): pc/sp/ir/flags lex as REGISTER tokens and parse as operands, but SymbolResolver.resolveOperand returns a null value for them, so InstructionWordEncoder.reg() throws NullPointerException. Repro: mov r1, pc.
- B5 (MEDIUM, assembler): directive alignment is inconsistent - SymbolResolver only checks .word, DirectiveDataEmitter requires every .word/.byte/.ascii to start 4-byte aligned and fails at encode time; and AssemblerCli.writeBinary steps in 8-byte strides, so with '.org 0x100 / .word A / .word B / halt' it silently writes zeros for the second .word and the halt (the GUI export writes them correctly).
- B6 (MEDIUM, spec drift): ISA_SPECIFICATION.md lists HALT as 0x05 but OpCode.HALT is 0x03; the STORER formula is written RAM[Rd+imm]=Rs1 but the code does RAM[Rs1+offset]=Rd.
- B7 (LOW, cpu): DIV and MOD never touch C/V (they keep stale values) while AND/OR/XOR/NOT/shifts clear them; division-by-zero behavior not yet characterized.
- B8 (LOW, cpu): StackOverflowException is thrown for both push-past-limit and pop-from-empty; the second is an underflow.
- B9 (LOW, tooling): AssemblerCli has no main() and pom.xml configures no runnable entry point, so there is no command-line assembler today; the GUI no longer uses it.

### Out of Scope

- CALL/RET (already fixed in 90bf884).
- Language/compiler work (LANG-001 and downstream), GUI features, label reconstruction in the disassembler.
- New instructions or condition codes.

### Topology

isa (OpCode, Condition, InstructionDecoder) <- assembler (lexer, parser, resolver, encoder) and disassembler <- gui. The decoder and the encoder must stay mirror images: any change to immediate range or extension is made in both, plus the spec and the disassembler, in the same change.

### Steps

- Align on decisions (a)-(e) in Notes and record the answers here.
- B1 + B3: fix decoder immediate handling and define per-instruction extension; add decoder and disassembler tests over boundary words (0x7FFFFFFF, 0x80000000, 0xFFFFFFFF).
- B2: add unary minus to the lexer/parser, update the encoder range check and its error text; round-trip test with negative immediates.
- B4: reject special-register operands with a proper diagnostic (or implement them).
- B5: move alignment checks to resolve time with one rule; make AssemblerCli and the shared pipeline emit identical bytes.
- B6: reconcile ISA_SPECIFICATION.md and OpCode/Cpu for HALT and STORER.
- B7/B8/B9: apply the agreed decisions and document them.
- Update docs/ASSEMBLY_GUIDE.md section 9 and the GUI's OpcodeReference notes to match; delete notes for anything fixed.

### Hazards

- Encode/decode drift is the core risk: assembler range check, decoder, disassembler and spec must change together.
- Zero-extend versus sign-extend per instruction is easy to get wrong silently, especially for ANDI/ORI/XORI masks with the top bit set.
- Math.toIntExact-style narrowing elsewhere may hide the same bug; grep for it when fixing B1.
- Bundled examples and the GUI must keep working: run every program in src/main/resources/programs after each step.
- The GUI disassembly panel feeds arbitrary memory words into the decoder, so decoder regressions show up there first.
